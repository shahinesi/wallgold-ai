# راهنمای امن ساخت و ثبت API Key وال‌گلد

> اصل مهم: **API Key وال‌گلد را داخل ChatGPT، Codex، Prompt، ورودی MCP Tool، Issue، لاگ یا اسکرین‌شات عمومی قرار نده.** مدل برای کارکردن به دیدن خود کلید نیاز ندارد.

مستندات رسمی:
- https://developers.wallgold.ir/fa/docs/api-key
- https://developers.wallgold.ir/fa/docs

## استفاده شخصی / یک حساب

1. وارد حساب/اپ WallGold شو و بخش **مدیریت API** را باز کن.
2. یک نام مشخص برای کلید انتخاب کن؛ مثلاً `wallgold-copilot-private`.
3. اگر WallGold اجازه می‌دهد، **IP عمومی خروجی سروری که MCP روی آن اجرا می‌شود** را در allowlist قرار بده. برای اجرای واقعی سفارش، IP ثابت بهتر از IP خانگی/پویا است.
4. مدت اعتبار کلید را آگاهانه انتخاب کن. طبق راهنمای فعلی WallGold گزینه‌های ۳۰، ۶۰ و ۹۰ روز وجود دارد؛ برای production باید قبل از انقضا فرآیند rotation داشته باشی.
5. ساخت کلید را با کد پیامکی تأیید کن.
6. کلید فقط یک‌بار نمایش داده می‌شود؛ همان لحظه آن را در Secret Manager یا فایل `.env` محلیِ خارج از Git ذخیره کن.
7. در این پروژه:

```bash
WALLGOLD_API_KEY=YOUR_SECRET_VALUE
```

8. بعد از نصب dependencyها، اتصال را بدون چاپ secret تست کن:

```bash
npm run smoke:wallgold
```

یا از MCP Tool زیر استفاده کن:

```text
check_wallgold_connection
```

این ابزار فقط نتیجه دسترسی، ارزهای موجودی و TTL قیمت نمونه را نشان می‌دهد و secret را برنمی‌گرداند.

## چرخش و ابطال کلید

- تاریخ ایجاد و تاریخ انقضای کلید را در سیستم عملیاتی ثبت کن.
- چند روز قبل از انقضا کلید جدید بساز، Secret Manager را update کن، سرویس را restart/redeploy کن و اتصال را تست کن.
- کلید قبلی را بعد از موفقیت کلید جدید revoke کن.
- اگر احتمال نشت کلید وجود دارد، منتظر تاریخ انقضا نمان؛ فوراً revoke/rotate کن.
- API Key را در audit log یا exception body ذخیره نکن.

## نسخه چندکاربره / قابل انتشار عمومی

برای محصولی که کاربران مختلف WallGold خودشان را وصل می‌کنند، `WALLGOLD_API_KEY` سراسری معماری درست نیست. مهم‌تر از آن، در Plugin عمومی OpenAI نباید از کاربر API Key، OTP، password یا secret احراز هویت بخواهیم یا آن را پردازش کنیم. بنابراین «فرم گرفتن API Key از کاربر» را هم به‌عنوان مسیر انتشار عمومی توصیه نمی‌کنیم.

مسیر درست برای انتشار عمومی:

```text
ChatGPT / Codex
      │ OAuth 2.1 کاربر با سرویس شما
      ▼
WallGold Copilot Gateway
      │ اتصال رسمی / token delegation مورد توافق WallGold
      ▼
WallGold API
```

- برای اتصال حساب‌های واقعی کاربران، با WallGold یک integration رسمی و روش تفویض دسترسی بگیرید؛ ترجیحاً OAuth/token exchange یا credential مخصوص partner که کاربر مجبور به ارسال API Key خام نباشد.
- MCP شما برای هویت کاربر از OAuth 2.1 استفاده کند و scopeها را روی هر ابزار enforce کند.
- هیچ Tool input/result، Skill، UI metadata یا لاگی نباید API Key/OTP/password داشته باشد.
- تا زمانی که WallGold روش رسمی چندکاربره ارائه نکرده، قابلیت‌های account-specific را private/self-hosted نگه دارید و نسخه عمومی را به تحلیل بازار و داده‌های عمومی محدود کنید.
- نسخه عمومی Plugin نباید ابزار اجرای خرید/فروش سرمایه‌گذاری را expose کند.

## چیزی که کاربر باید بفرستد

در استفاده شخصی، کاربر **خود API Key را برای مدل نمی‌فرستد**؛ آن را مستقیم در secret محیط اجرا ثبت می‌کند.

برای **استفاده خصوصی یا سازمانی خارج از Plugin عمومی OpenAI**، اگر تیم فنی مجبور است کلید را دریافت کند، از یک مسیر secret-management اختصاصی و کنترل‌شده استفاده کنید؛ نه چت یا ایمیل. برای Plugin عمومی، طراحی را طوری عوض کنید که اصلاً API Key خام کاربر جمع‌آوری یا پردازش نشود.
