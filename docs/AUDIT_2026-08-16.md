## Audit سازگاری ChatGPT / Codex

| موضوع | نتیجه |
|---|---|
| داده حساب شخصی / ابزارهای حساب | برای انتشار چندکاربره باید MCP با OAuth 2.1 کاربر را احراز و scopeها را enforce کند |
| API Key / OTP / password | در Plugin عمومی نباید از کاربر جمع‌آوری، درخواست یا پردازش شوند |
| اجرای خرید/فروش سرمایه‌گذاری | در Plugin عمومی مجاز نیست؛ `execute_private_trade` فقط private و opt-in است |
| اتصال سرویس شخص ثالث | انتشار عمومی به مجوز/همکاری WallGold و رعایت شرایط آن نیاز دارد؛ connector غیررسمی pass-through مسیر قابل اتکایی برای review نیست |
| Transport production | MCP راه‌دور باید روی endpoint پایدار HTTPS با Streamable HTTP ارائه شود |
| Codex محلی | STDIO برای private/local development نگه داشته شده است |

بنابراین repo عمداً دو سطح دارد: **private/self-hosted** برای قابلیت‌های حساب و اجرای guarded، و **public-compatible surface** برای تحلیل/داده عمومی؛ account-specific public فقط بعد از auth رسمی تکمیل می‌شود.

## مواردی که عمداً هنوز «کامل خودکار» نیستند

### 1. اتصال چندکاربره عمومی

کد فعلی private/single-user از یک secret سرور استفاده می‌کند. برای Plugin عمومی، صرفاً اضافه‌کردن یک vault برای API Key خام کاربران کافی نیست و با محدودیت credentialهای Plugin عمومی تعارض دارد. مسیر صحیح این است که MCP با OAuth 2.1 کاربر را احراز کند و اتصال WallGold از طریق integration رسمی/تفویض دسترسی مورد توافق WallGold انجام شود؛ تا آن زمان account-specific access باید private/self-hosted بماند.

### 2. اجرای معامله در Plugin عمومی

Execution tool فقط در private mode و با env صریح register می‌شود. تا قبل از اتصال رسمی چندکاربره WallGold، نسخه عمومی فقط تحلیل و داده‌های عمومی را ارائه کند؛ پس از تکمیل OAuth 2.1 و اتصال رسمی می‌توان portfolio/quote/preview وابسته به حساب را اضافه کرد. اجرای واقعی معامله همچنان نباید منتشر شود.

### 3. News / Macro / XAU / USDIRR provider مستقل

`analyze_gold_market` خودش اینترنت را scrape نمی‌کند؛ یک deterministic evidence aggregator است. در ChatGPT، Skill از Web Search میزبان داده تازه را جمع می‌کند و Evidence Engine عدد نهایی را محاسبه می‌کند. برای daemon مستقل 24/7 باید providerهای اختصاصی price/news/macro اضافه شوند.

### 4. کارمزد preview

Market coefficient و order response در دسترس‌اند، اما preview فعلاً fee را از موجودی فرضی کم نمی‌کند؛ پاسخ واقعی `otcFee` بعد از سفارش source of truth است. این انتخاب محافظه‌کارانه است تا بدون قرارداد قطعی تسویه fee، موجودی ساختگی تولید نشود.

### 5. Persistence production

JSON store برای private prototype است. claim اجرای preview در یک process اتمیک شده، اما production چند-instance به DB transactional، unique constraint روی execution claim/clientId، tenant isolation و audit immutable نیاز دارد.

## نتیجه Audit

قرارداد WallGold در مسیر critical execution اکنون با docs فعلی همسو شده است: balance semantics، quote TTL، live market constraints، order fields و reconciliation لحاظ شده‌اند. باقی‌مانده‌های اصلی دیگر bug endpoint نیستند؛ **production architecture** هستند: OAuth 2.1، integration رسمی چندکاربره با WallGold بدون دریافت API Key خام در Plugin عمومی، providerهای autonomous داده، DB و deploy/review رسمی.
